# M1.5 Decision Report — 是否进入 M2 的产品决策输入

> ImagineOS Alpha · 2026-10-06 · M1.5 Expression Quality Gate 收口决策报告
> 读者：产品负责人。回答 7 个决策问题，全部标注证据等级（A=可复现持久化 / B=持久化不可复现 / C=引用 / ⏸=待补跑）
> 原则：**没有验证的数据写「未验证」。不为了「看起来完成」而给结论。**

---

## Q1. 普通人的自然表达，是否已经能稳定变成有价值的视频作品？

**分层回答：**

| 层 | 判定 | 证据 |
|----|------|------|
| 表达 → 结构化作品 | **已证明** | 10/10 类型 Intent 编译零失败（77 次 text.plan 全成功）；三范式真实分化；端到端干净窗口 121–262s（A） |
| 作品 → 有价值的视频体验 | **部分证明，天花板已量化** | 组合式成片 =「动的图片」（YDIF≈1.0，B/C 级证据）；Native 路径运动量 2.1×（A 级 smoke），但未做全案例验证（⏸ Golden Case） |
| 作品 → 被看见 → 诱发再创作 | **未验证** | 需 Gate 7 真人测试（「我还想做一个」行为率）；系统侧已就绪（导出/批量完整性/指标关联全部实测可用） |

**结论**：表达链路「能走通」已被 9 个真实发布案例证明；「有价值」的视觉上限被量化约束在 Ken Burns 级别；「值得被看见与接力」完全没有行为数据。**M1.5 的使命（验证表达链路 + 量化天花板）达成度 ≈85%，剩余 15% 是配额阻塞的行为链证据（G3/G4/p10/Native，脚本就绪）。**

## Q2. 当前最大的产品瓶颈是什么？

**排序：① AI 生成质量（视觉运动）＞ ② 内容传播（未验证）＞ ③ Intent 理解 ≈ Revision ≈ UX。**

1. **视觉质量**是唯一被量化证实的短板：YDIF 1.0（组合式）vs 2.08（Native smoke）vs 实拍 3–8——观众第一眼价值由它决定（A/B 级证据）；
2. **内容传播**是未验证的下一环，且逻辑上依赖视觉质量先达标——为静态画面做分发是负资产；
3. **Intent 理解**表现良好（77 次全成功、10 类型零失败）但未经过真人自由表达的多样性考验（脚本表达 vs 真人表达有分布差）；
4. **Revision/Remix** 机制层满分（六不变量 DB 级全过），行为层待补（⏸）；
5. **UX** 无负面证据，真人测试才是考场。

另有一个**工程级瓶颈**（非产品瓶颈）：provider 配额长冷却（当日 ~360 次调用后小时级不可用）——影响的是测试与开发效率，Alpha 用户单案例 ~28 次调用的量级暂不构成产品约束。

## Q3. Native Video 是否值得进入下一阶段主路径？

**当前证据不足以定论（这正是 Golden Case 存在的原因），但决策框架已清晰：**

| 维度 | 已知 | 未知 |
|------|------|------|
| 质量 | 运动量 2.1×、含主体运动（A 级 smoke） | 全案例（≥5 镜）的连贯性/一致性/观感（⏸） |
| 延迟 | 单镜 56s（A） | 全 native 端到端（预计 +4.7min，⏸） |
| 成本 | 每镜 +1 次视频调用（配额压力 ≈ 翻倍） | 成功率与回落率（⏸） |
| 稳定性 | 回落机制在位（Provenance 记账） | 真实失败率（⏸） |

**预注册判定标准**（Golden Case 后按此裁决，不事后放宽）：
- **值得升为主线**：≥4/5 镜 native 成功、无一致性灾难（首帧↔视频主体漂移）、观感明显优于组合版、每镜延迟 ≤90s；
- **值得并行深化**：出现回落但主体运动质量显著；
- **不值得**：一致性灾难或延迟/成本失控。

**方向性判断（可被 Golden Case 推翻）**：Native 更可能以「调度策略」进入产品（哪些镜头值得动起来），而非全量替换组合式——组合式的成本/延迟/确定性仍是叙事视频的合理基线（ADR-0001 Rev.2 双路径决策的延续）。

## Q4. Revision 是否已经足够可靠？

**机制层：是。行为层：未验证。**

- 机制（定位→新版本→局部重生成→changelog→旧版保留）在 DB 级全过（A 级）；
- 但「四连改」的**定位精度**（targetLevel/targetNode/affectedShotIndexes 是否符合人类预期）没有专项数据（⏸ 脚本就绪，预注册了判定标准：镜 2 替换请求 changedShotCount 必须恰好 =1 等）；
- 已知风险：修订定位是最慢的 LLM 调用（15.1s，全量结构输入）——M2 若做实时交互需优化为增量输入。

**判定：暂不能给「可靠」结论。四连改补跑是 Q4 的唯一证据源。**

## Q5. Remix 是否真的形成 Creation Loop？

**数据层闭环成立；行为层闭环未证明。**

- 成立的部分（A 级）：8 条真实血缘，继承（Intent 语境+配方字节级）/隔离（资产独立）/零改动（原作只追加事件）/双侧溯源/两层查询全部 DB 级验证；§63 种子的 Remix 副本真实再生成过自己的像素；
- 未证明的部分（⏸ + 人工）：「换母亲」级的语义修改在 Remix 语境下是否被正确理解；真人是否会自然点「从这里开始创作」并走完 ≥1 步（Gate 7 探索段指标）。

**判定：Creation Loop 的「管道」已铺好且不漏水；「水流」（人的行为）尚无数据。**

## Q6. 什么时候应该进入 M2？

**进入条件（全部满足才进，缺一延后）：**

1. ✅/⏸ **M1.5 行为链证据补齐**：G3 四连改 + G4 Remix 链 + p10 + Native Golden Case 跑完且报告更新（预计配额恢复后 ~40 分钟机器时间）；
2. ⏸ **Gate 7 真人测试执行**：≥10 人完成 30 分钟流程，得到 Expression Success 率与「我还想做一个」行为率（人工阶段，系统侧已就绪）；
3. ✅ **数据完整性绿**：0 错 0 警（已达成并复验）；
4. ✅ **无 P0 级缺陷遗留**：当前已知缺陷均为 P1/P2（User 硬删除外键、contents API 语义收敛、多画幅）。

**时间预估**：条件 1 在配额恢复当日完成；条件 2 取决于招募（计划建议 1–2 周窗口）。**在此之前严格遵守指令：不做 Follow/Comment/私信/Feed 推荐大系统/社交关系/大型 Profile/类 TikTok 体系/分布式重构/Redis-Kafka 升级/提前重构 Content Object。**

## Q7. M2 第一主线应该是什么？

**两轮证据收敛后的建议（待 Q6 条件 2 的真人数据裁决）：**

- **主线 A（默认推荐）——视觉质量深化**：Native 路径产品化（镜头级调度策略：哪些镜头值得 native——情绪高潮/主体动作镜头优先）+ 首帧一致性（角色锚定）+ 失败回落的用户语言化（「这一镜我们让它真正动起来」）。理由：它是唯一被量化证实的最大短板（Q2 排序第一），且 ADR-0001 Rev.2 双路径架构已为此铺好路；
- **主线 B（条件触发）——内容侧最小验证**：若真人测试「我还想做一个」≥30% 且 Expression Success ≥50%，则 Explore 分发 + Remix 转化漏斗（先于任何社交功能）升为并行主线；
- **明确的非主线**：社交体系（Follow/Comment/Feed）、基础设施升级——在表达→创作→观看→修改→发布→从作品继续创作的闭环被真人行为证实之前，全部冻结。
