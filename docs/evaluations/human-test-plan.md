# Human Test Plan — M1.5 Gate 7（真人表达测试）

> ImagineOS Alpha · 2026-10-06 · 状态：Ready-to-run
> 本计划回答一个问题：**普通人在没有被告知"怎么用"的情况下，能否把心里想表达的东西变成一件让他们自己满意的作品？**

## 1. 目的与可证伪假设

Gate 1–6 验证的是机器侧（管线质量、数据完整性）。Gate 7 验证人这一侧。北极星指标 Expression Success Rate 只能由真人测试度量，实验室脚本无法替代。本轮测试对应项目宪章中的四个假设：

- **H1（表达→作品）**：用户说一句自然语言，系统能完成 Intent 理解并产出结构完整的作品；
- **H2（修订）**：用户看到初稿后，会用自然语言继续修改，而不是放弃；
- **H3（发布意愿）**：用户愿意让作品被别人看见（Publish）；
- **H4（创作冲动传染）**：用户看到别人的作品后产生"我也想做一个"的行为（Remix 或新建）。

**尤其关注的单一句子**：测试者说出"我还想做一个。"——这是 Creation Loop 取代 Consumption Loop 的第一信号，观察员应在记录表上专门勾选此项。

## 2. 招募标准

10–20 位（目标 16 位，容许 10 位起步），配额维度：

| 维度 | 配额要求 | 理由 |
|------|----------|------|
| 创作经验 | ≥70% 无视频剪辑/设计经验 | 验证"普通人"命题，会剪映的人会把问题归因于自己而非系统 |
| 年龄 | 至少覆盖 20–30 / 30–45 / 45+ 三段 | 表达欲与语言习惯差异是 Intent 理解的真实分布 |
| 性别 | 尽量均衡 | 题材分布依赖（家庭/情绪/知识类表达） |
| 设备 | 手机为主（≥60%），桌面为辅 | 产品主场景是竖屏 9:16 |

**排除标准**：参与过本项目开发或评审的人；AI 生图/生视频的重度用户（他们的 Prompt 习惯会污染"不教 Prompt"的设计）。

## 3. 测试流程（30 分钟/人）

### 3.1 开场脚本（必须照读，不得展开）

> "这是一个新东西，叫 ImagineOS。**告诉它一件你想表达的东西。**你想说什么都行——一个人、一件事、一个心情、一个梦都可以。"

**禁止行为**（观察员自律清单）：
- 不得说"输入提示词 / prompt / 描述画面 / 帮 AI 写清楚一点"；
- 不得替测试者选择方向、故事、分镜；
- 测试者提问"我该说什么"时，只重复开场句 + "你最近心里在想什么？"；
- 测试者卡住超过 3 分钟才允许说"也可以是很小的事"。

### 3.2 自由创作段（0–15 分钟）

观察员静默记录（见 §5 指标），不干预。测试者自然走完：表达 → 看方向 → 挑一个 → 故事 → 分镜 → 生成 → 预览。

### 3.3 修订段（15–22 分钟）

初稿出现后，观察员只说一句：

> "这是它给你做的第一版。你可以就这样发出去，也可以告诉它你想改哪儿。"

（同样不解释"能改什么"。修订行为是否自然发生，本身就是测量对象。）

### 3.4 探索段（22–28 分钟）

> "发布之后它会出现在'探索'里。你可以在探索里看看别人的作品。"

静默观察：是否点开别人的作品？停留多久？是否出现 Remix 点击（"从这里开始我的版本"）？是否说"我还想做一个"？

### 3.5 收尾访谈（28–30 分钟）

三个开放问题（录音+速记）：
1. "刚才这个过程，哪里让你觉得'它是懂我的'？哪里让你觉得'它不懂'？"
2. "这件作品，你会发给谁看？为什么？（或为什么不会？）"
3. "如果明天还能用，你想再做一个什么？"

## 4. 指标定义与操作化

| 指标 | 操作化定义 | 数据源 |
|------|-----------|--------|
| Intent completion | 开场表达后 5 分钟内到达"挑选方向"步骤，且访谈能确认"方向里有我想要的" | 屏幕录制 + 访谈编码 |
| First result satisfaction | 初稿出现后首个自发反应编码：正（惊喜/笑/发给旁边人看）/ 中（沉默浏览）/ 负（皱眉、"这不对"） | 录像回放双人编码，分歧仲裁 |
| Revision behavior | 是否发生 ≥1 次自然语言修改；修改输入的类别（情绪/内容/时长/结构/角色）；修改后满意度变化 | 系统日志（Revision 记录）+ 录像 |
| Publish intention | 是否发布；未发布者的理由编码（不想被人看到 / 不满意 / 隐私） | 系统日志 + 访谈 |
| Remix intention | 探索段是否点击"从这里开始我的版本"；点击后是否继续走 ≥1 步 | 系统日志 |
| Repeat creation intention | 收尾问答出"还想做一个什么"的具体内容（非敷衍）；或会话内自发新建第二个作品 | 访谈 + 日志 |

**主指标（一票汇总）**：Expression Success = Intent completion ∧ First result satisfaction ≥ 中 ∧ (Published ∨ 明确表达满意)。目标线：≥50%（Alpha 阶段）。

**"我还想做一个"行为率**：单列。目标线：≥30%。这是 M2 是否值得做内容传播侧的唯一判据。

## 6. 判定标准（M2 范围决策输入）

| 结果模式 | 结论 |
|----------|------|
| Expression Success ≥50% 且"还想做一个"≥30% | M2 可进入内容传播侧（Explore/Remix 强化） |
| Expression Success ≥50% 但"还想做一个"<30% | 瓶颈在内容传播侧，M2 聚焦 Explore 分发与作品呈现，暂缓社交功能 |
| Expression Success <50%，修订行为少 | 瓶颈在生成质量/Intent 理解，M2 聚焦 Native Video 路径与 Intent 访谈优化，暂缓一切社交 |
| 满意度高但发布意愿低 | 作品私域价值成立，M2 优先私域分享链路（发给一个人）而非公开探索 |

## 7. 伦理与知情同意

- 测试前口头知情同意 + 一页纸说明（录像用途、可随时中止、数据匿名化）；
- 测试者作品的可见性默认 private，仅在其主动发布时公开；
- 录像与访谈记录仅用于产品迭代，不用于任何对外展示（除非另行取得授权）；
- 观察员不得替测试者发布任何内容。

## 8. 执行时间表（建议）

| 阶段 | 内容 | 工作量 |
|------|------|--------|
| D0 | 招募 + 场地/设备确认（手机用测试 Wi-Fi，避免网络变量） | 2 天 |
| D1–D3 | 每天 4–6 人，单人 30 分钟 + 15 分钟整理 | 3 天 |
| D4 | 双人编码校准 + 数据汇总 + 与 §Gate 1–6 报告交叉分析 | 1 天 |
| D5 | Human Test Report + M1.5 Decision Report 终稿 | 1 天 |

## 9. 与 M1.5 其他 Gate 的衔接

Gate 1–6 的结论决定本测试的"底座可信度"：Content Integrity Report 保证测试中观察到的 UI 行为与数据层一致（不会出现"看起来发布了其实没发布"）；Visual Quality Report 的双路径结论（Composition vs Native）在测试中按当日配置记录——若测试期使用 Native 路径，需在报告中注明对比条件。

本测试产生的所有真实用户作品，自动进入 Golden Dataset（docs/evaluations/README 的回归触发器），成为后续每次管线改动的回归基线。
